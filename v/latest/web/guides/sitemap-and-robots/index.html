Sitemap and robots.txt

@warlock.js/web/sitemap turns your page graph into a sitemap.xml. It uses the framework-independent @warlock.js/sitemap builder for the XML. Web finds the pages, applies each page’s config.sitemap, and expands locales into hreflang alternates. It generates at runtime boot or when the app requests regeneration, and serves /sitemap.xml and /robots.txt. Both features are off until you enable them.

Turn it on

Section titled “Turn it on”

This adds a disabled sitemap section to src/config/web.ts. It creates the file if needed and otherwise merges into the existing file. Set the app’s public origin, then enable the sitemap:

The sitemap has no baseUrl key. The origin always comes from app.publicUrl, or from PUBLIC_APP_URL when app.publicUrl isn’t set.

MissingPublicUrlError

If the sitemap is enabled and neither app.publicUrl nor PUBLIC_APP_URL is set, generation throws MissingPublicUrlError before it reads any page. It never builds URLs from a guessed host. At boot, the error is logged and the app still starts, but /sitemap.xml returns 503.

web.sitemap

Section titled “web.sitemap”

| Key | Default | Meaning | | ------------ | ------------------------ | ---------------------------------------------------------------------------------------- | | enabled | false | Nothing is discovered, generated, or served until this is true. | | path | "/sitemap.xml" | Where the sitemap, or the index for a large site, is served. | | outputDir | storagePath("sitemap") | Where generated files are written. The sitemap must be the only thing in this directory. | | gzip | false | Writes shards as .xml.gz when the index path is used. | | defaults | — | { changefreq?, priority? }, used for any URL that doesn’t set its own values. | | locales | — | { codes?, defaultLocale?, splitByLocale? }. See Locales. | | localeUrl | — | (path, localeCode) => string. Overrides how a locale’s URL is built. | | regenerate | { onBoot: true } | onBoot: false skips generation at boot. |

outputDir is replaced as a whole

Each publish swaps the entire outputDir atomically. Never point it at public/ or any other directory that holds other files. The package refuses to replace a non-empty directory it didn’t create, and throws UnownedOutputDirectoryError. Files are served from outputDir, so the default storage/sitemap doesn’t change any public URL.

What goes into the sitemap

Section titled “What goes into the sitemap”

Every routable page is considered. The not-found page and error.page.tsx are never included. Each page can control its entries with config.sitemap:

| Page | Its config.sitemap | Result | | ---------------------- | -------------------------- | --------------------------------------------------- | | Static route | none | One URL at the route’s path. | | Static route | an options object | One URL, with those options. | | Static route | a function | The URLs the function returns. | | Dynamic route ([id]) | a function | The URLs the function returns. | | Dynamic route | none, or an options object | No URLs. The route is reported with count: 0. | | Any route | false | Left out, and not reported. |

A pattern like /posts/:id is not a URL, so a dynamic route needs a function that returns its concrete paths:

Pass options to a static page, or opt a page out:

| Options field | Meaning | | ----------------------------------- | ------------------------------------------------------------------------- | | priority, changefreq, lastmod | Per-page values. They take precedence over web.sitemap.defaults. | | locales: false | The page is the same in every locale. It gets one URL with no alternates. | | localePaths | { [code]: path }, for pages whose slugs differ by locale. |

Each URL a function returns can set path, lastmod, changefreq, priority, and its own localePaths.

A dynamic route with no function doesn’t disappear without a trace. It shows up in the generation result’s routes with count: 0. See the route diagnostic.

Locales

Section titled “Locales”

Locale codes come from app.localeCodes, with app.localeCode as the default. With one or more codes configured, each URL becomes one <url> per locale, and each carries the complete set of hreflang alternates, including itself. Setting defaultLocale adds an x-default alternate that points at the page’s plain path.

Warlock doesn’t route by URL prefix. A request’s locale comes from the ?locale= query, then the cookie, then the header. So the default locale URL is the page’s path with ?locale=<code> added (&locale= if the path already has a query string). If your app routes by prefix itself, provide localeUrl:

A page’s own localePaths take precedence over both. locales.splitByLocale: true writes one set of shard files per locale, listed in one index.

With web.localeRouting.strategy, generated locale URLs, hreflang alternates, and x-default use the same prefix rule as the router. A leading [locale] route substitutes the visited locale segment. A page’s config.sitemap.localePaths or web.sitemap.localeUrl still overrides the derived URL where an application has translated slugs.

Page and layout policy

Section titled “Page and layout policy”

Sitemap policy is server/build configuration, not a top-level page export. Put a page supplier or option object in config.sitemap as shown above. A positional layout may provide only a static sitemap default; descendants use the nearest layout default unless their own page config supplies a value. A layout cannot supply dynamic URLs. Layout metadata is likewise limited to a static metadata.robots default. Put site-wide robots.txt and sitemap settings in src/config/web.ts; root.tsx accepts middleware and the static strictMode flag and does not contribute metadata or sitemap inheritance.

Large sites

Section titled “Large sites”

Up to 50,000 URLs, web writes one sitemap.xml. Above that, or when splitByLocale is on, it switches to SitemapIndex. The index is served at web.sitemap.path, and each shard (sitemap-0001.xml, sitemap-en-0001.xml, or .xml.gz with gzip: true) is served at the site root. See Large sites.

When it’s generated

Section titled “When it’s generated”
  • Boot, in development and production, registers the routes and then generates, unless regenerate.onBoot is false. A failure at boot is logged and the app still starts. warlock build does not generate the sitemap.
  • A request never triggers generation. /sitemap.xml serves the last set that generated successfully. Before the first successful run, it returns 503 with Retry-After.

When your data changes, for example a new product or post, regenerate from an event, a schedule, or a job. Never do it from a request handler:

regenerateSitemap() joins a run that is already in progress instead of starting a second one. If a run fails, the previous set is still served and the error is written to stderr. generateSitemap() does the same work but doesn’t update what the routes serve. Use it in scripts and tests.

web.robots

Section titled “web.robots”

When web.robots.enabled is true, web serves GET /robots.txt with one User-agent block per group, then the extra lines, then the Sitemap: line. The Sitemap: line appears only when the sitemap is enabled and has an origin. A missing origin never breaks robots.txt.

If public/robots.txt exists, web registers no route and logs a warning. Your file is served as is, so add the Sitemap: line to it yourself.
